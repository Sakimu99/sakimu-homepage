## 一、审核到底在看什么

「无实质经营内容」不是技术问题，是**看不出你在卖东西**。审核方通常按四条判断：

| 判据 | 之前的站点 | 现在 |
| --- | --- | --- |
| 有明确在售的商品/服务 | 只有一段「服务介绍」文案，没有条目化清单 | ✅ 六类服务，逐条列出包含项与交付物 |
| 有价格 | 只有「定金 ¥5」，没有服务价格 | ✅ 每类服务标明起步价与工期 |
| 有下单到支付的闭环 | 首页一个表单直接跳支付宝 | ✅ 表单 → **站内订单支付页** → 支付宝 |
| 有真实经营主体与规则 | 页脚只有备案号 | ✅ 主体全称、城市、邮箱、条款/隐私/退款 |

补一条隐含要求：**页面必须属于本站**（域名一致、不跳外站）。站内支付页解决了「支付页是别人的域名」这个尴尬。

## 三、三张截图的拍摄要求

### 3.1 硬性要求

- **必须含浏览器地址栏**，能看清 `sakimu.cn`（用备案域名，不要 `*.pages.dev`）。
- **不要 F11 全屏**（全屏会隐藏地址栏）。
- **不要裁剪掉地址栏**，也不要把多张图拼成一张。
- 页面内容要**滚到能看见价格/按钮**的位置，不要截大片空白。
- 关闭广告拦截、翻译插件（避免页面顶部出现插件横幅）。
- 用**未登录的普通窗口**截（别让浏览器显示你的书签/头像信息）。

### 3.2 推荐截法（Windows）

1. 打开 Chrome，窗口**不要最大化**（留点边距），宽度拉到 1280 以上。
2. 地址栏输入目标 URL，等页面完全加载（图片、字体都出来）。
3. 按 `Win + Shift + S` → 选「矩形」→ **从地址栏上沿开始框**，框到页面底部（或按钮区域）。
4. 保存为 PNG，命名建议：`首页.png` / `服务与报价.png` / `订单支付.png`。

> 或者：`Alt + PrtSc` 截当前活动窗口（天然含地址栏），再裁掉多余的桌面部分。

## 六、万一还被拒，怎么对

| 驳回理由 | 对应处理 |
| --- | --- |
| 仍说「无实质经营内容」 | 把价格做成更大的可视区块（首页也放价格），补「客户案例」真实截图，补统一社会信用代码与客服电话 |
| 「网站无法访问」 | `sakimu.cn` 在国内部分网络有丢包（实测约 50%），这会直接影响审核。**这是目前最大的外部风险**，见下一节 |
| 「经营类目不符」 | 按营业执照经营范围改类目，并在「网站内容说明」里写明 |
| 「网站内容与主体不符」 | 页脚主体全称与营业执照逐字一致 |

### 关于 `sakimu.cn` 的国内可达性（重要）

之前实测：`sakimu.cn` 解析到 Cloudflare 的 `172.67/104.21` 段，从国内网络访问**约一半请求超时**；
同一站点的 `*.pages.dev`（`172.66` 段）则稳定。审核方如果用国内网络打开，有概率遇到打不开——
一旦被判「网站无法访问」，材料再全也没用。

**建议**（二选一）：
1. 把站点迁到国内服务器（你已有腾讯云 `106.53.138.57`，`www` 已指向它），支付后端用现成的 Node 实现；
2. 或提交前用国内手机流量实测 10 次，能稳定打开再提交。
